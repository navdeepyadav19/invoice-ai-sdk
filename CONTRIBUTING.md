# Contributing

## Setup

Requires Node 20+, pnpm (`corepack enable`), and [uv](https://docs.astral.sh/uv/) for the Python SDK.

```bash
pnpm install
pnpm build            # TypeScript SDK + CLI
pnpm test             # TypeScript SDK + CLI unit tests
(cd packages/sdk-python && uv run pytest)
```

## The spec and generated code

`spec/openapi.json` (and `spec/currency.ts`, the server's currency-decimals table)
are owned by the API repo, [navdeepyadav19/invoice-ai](https://github.com/navdeepyadav19/invoice-ai).
When its `api-docs/openapi.json` changes on `main`, a workflow there opens a PR here
with the new spec and regenerated SDKs.

Never edit generated files (they start with `Generated by scripts/sdk-gen`). Change
the API in the API repo, or change the generators in `scripts/sdk-gen/` and run
`pnpm sdk:gen`. CI fails if the committed SDKs don't match the spec.

## Releasing

1. In your PR, run `pnpm changeset` and describe the change. The TypeScript SDK and
   CLI always share a version; the Python SDK follows it.
2. After merge, the Release workflow opens a **Version Packages** PR.
3. Merging that PR publishes to npm (with provenance) and PyPI (trusted publishing).

Rehearse a release with Actions → Release → Run workflow (`rc.0`): it publishes
`X.Y.Z-rc.0` under the npm `next` tag and `X.Y.Zrc0` on PyPI.

## CLI login contract

`invoice-ai login` uses a device authorization flow (RFC 8628) implemented in the API
repo, outside the OpenAPI spec:

| Endpoint | Purpose |
|---|---|
| `POST /api/cli/device` `{client_name, client_os}` | returns `device_code`, `user_code`, `verification_uri(_complete)`, `interval`, `expires_in` |
| `POST /api/cli/token` `{device_code}` | `200` once with `{api_key, key_id, scopes, account}`; otherwise `400 {error}`: `authorization_pending`, `slow_down` (+5s), `access_denied`, `expired_token`, `invalid_grant` |
| `DELETE /api/cli/session` (Bearer key) | revokes the key; `204` |

Changes to these endpoints must stay backward compatible with published CLI versions.
